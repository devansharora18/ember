# Competitor teardown

The output is a decision about where to differ, not a feature list.

## 1. Pick the set

3–5 products: the obvious leader, the cheap alternative, the one for a different user, and one adjacent tool people actually use instead. Note why each is in the set.

## 2. Collect evidence, not vibes

For each: pricing page, docs, onboarding flow (sign up if free), changelog, and recent complaints on review sites or forums. Record quotes and links. Screenshot the flow that matters.

## 3. Matrix

| | A | B | C | Us |
|---|---|---|---|---|
| Primary user | | | | |
| Time to first value | | | | |
| Pricing model | | | | |
| Onboarding | | | | |
| Repeated complaint | | | | |

## 4. Read the gaps

- What do users complain about repeatedly? That is the opening.
- What does everyone charge for that is cheap to give away?
- What is table stakes you cannot skip?
- Where is the market crowded and undifferentiated? Do not enter there.

## 5. Differ

Write one sentence you could put on the homepage that no competitor could truthfully use. If it also fits them, it isn't differentiation.

## Rules

- Never copy copy, layouts, or assets. Reinterpret patterns.
- Separate observed fact from inference; label the inference.
- Two pages maximum. Decisions, not an archive.
